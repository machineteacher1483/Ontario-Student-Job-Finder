20-Day Update Implementation Plan

Concrete MVP-to-production workflow

1Build the source registry

Create a table of approved public sources: employer career pages, government job boards, school-friendly boards, and manually verified SME submissions. Store source name, URL, allowed collection method, update frequency and reliability score.

2Use legal collection methods first

Prefer official APIs, RSS feeds, public career-page search URLs, employer ATS feeds, partner feeds, and manual submissions. Do not scrape platforms that prohibit automated access or require login unless you have permission.

3Normalize each posting

Convert every record into the same schema: title, employer, city, province, source URL, program tags, industry, term, deadline, work format, paid/unpaid, eligibility, date collected and expiry status.

4Deduplicate records

Generate a unique hash from title + employer + city + term + source URL. If the same role appears on Indeed, Eluta and the employer site, keep the employer site as the preferred apply link.

5Map roles to student programs

Use keyword rules first: “supply chain” → Logistics/Business; “software/cloud/AI” → CS/IT/Data; “child/youth/support” → Psychology/Social Work/Health Sciences; “civil/BIM” → Engineering/Architecture.

6Run a verification pass

Before publishing, check whether the source page is still live, the deadline has not passed, the location is in Ontario, and the role is suitable for college/university students.

7Schedule every 20 days

Use GitHub Actions, Netlify Scheduled Functions, Vercel Cron, or a small Python script on a server. Run daily, but only refresh if the last successful update was 20+ days ago.

8Publish data separately from design

Store opportunities in /data/opportunities.json. The HTML page reads the JSON and renders cards. This lets you update data without redesigning the page.

9Add school/employer submission forms

Students, SMEs and career centres can submit leads through a form. New leads should enter “Pending review” status and only become public after manual verification.

10Track expired and hidden leads

Expired listings should not disappear. Mark them as “Archived / watch next cycle” because they reveal which employers hire students and when the next intake may open.

Recommended Technical Setup

Low-cost MVP stack
Frontend:  Static HTML + JavaScript, hosted on Netlify / Vercel / GitHub Pages
Data:      /data/opportunities.json or Supabase table
Forms:     Tally / Google Forms / Airtable / Supabase form table
Updater:   Python script + GitHub Actions daily schedule with 20-day gate
Review:    Google Sheet or Airtable admin view
Rule:      Employer official link wins over job-board duplicate links

Pseudo-schedule:
- Daily 9:00 AM ET: updater checks last_successful_refresh
- If days_since_last_refresh >= 20: collect + normalize + dedupe + verify + publish
- If source fails: keep old data but mark source as "needs review"
- If posting deadline passed: move to "Archived / watch next cycle"
